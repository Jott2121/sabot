faults (T2 baselines never stall and have 0 mapping detections). Disposition:

**Reproducibility gap — RESOLVED 2026-07-24, same day, and the numbers moved.** As
first published, the strict column was produced by this QC pass as a one-off analysis
over the per-cell flags text, and that analysis was **not a committed code path**: it
required classifying each registered anchor as injected-side or true-side, and that
classification was never persisted. Every input needed to redo it was published
(`runs/wave2/wave2-rows.json` carries the full FLAGS text for every cell and SPEC 10.4
carries all 30 anchor sets), but a third party could not re-derive the six numbers by
running committed code the way they can re-derive the published union.

That is now closed. `sabot/strict.py` persists the anchor classification with a stated
reason per dropped anchor, `tests/test_strict.py` (102 tests) asserts the
classification against the frozen `operator_specs.SPECS` so it cannot drift, and
`scripts/score_strict.py` regenerates `runs/wave2/STRICT-FLOOR.md` deterministically
with a `--check` mode for drift. **The recompute disagrees with this pass's stated
floors by +1 to +3 cells on the five standard rows and by -2 cells on the Magentic
row, so the committed figures supersede them.** No wave-2 headline moves: the union
surface is untouched by the strict scorer.

Two independent cross-checks say the disagreement is arithmetic in this pass's
row-level composition, not a difference in what "strict" means. The committed scorer
reproduces, exactly, two strict-family figures this ledger stated separately and
derived independently: **O4 mapping-only 14/143 = 9.8%** (finding 4) and
**values-only O5 = 83.9%** (the superseded-echo audit under "what survived"). A
definitional divergence would not land on both of those to the cell. Direction of the
correction is also the honest one to disclose: the standard-row floors were slightly
too LOW (this pass under-counted the floor, understating the result) while the
Magentic floor was too HIGH (over-counting the row that already carries the most
caveats).

Residual known conservatism in the committed floor, accepted and documented in
`sabot/strict.py`: three cell classes have no strict surface at all, because their
registered anchors cannot separate injected from true text — T4/O1 (`40 km` is a
substring of the true `140 km`, the disclosed footnote-7 slip), T1/O3 (`P-3117`
prefixes both sides), T5/O3 (the injection deletes the anchor word `sustained`). Those
cells score zero at the floor and non-zero in the published union, which is the floor
behaving as designed.

## Addendum — the judge sandbox incident (2026-07-24, mid-wave-2 judging)

At batch 5 of the first judge run, the pre-batch canary FIRED: the judge model
reached the filesystem through `Monitor` — a tool added to the Claude Code
harness AFTER the wave-1 DENY list was frozen — and its probe reply quoted the
canary contents verbatim, naming its own method. The instrument refused to run
(fail-loud held). This is the benchmark's second self-catch: wave-1's canary
caught retrieval-hook contamination; wave-2's caught denylist decay against an
evolving harness.

Closure (dated commit 8d8da85, disclosed): primary = empty tool ALLOWLIST
(`--allowed-tools ""`) + `--strict-mcp-config` with no config (zero MCP
servers); the DENY list stays as defense-in-depth, extended to every current
first-party tool. The probe itself was redesigned (frontier-consult-ratified)
into a two-arm config-drift gate: a permissive arm with tools enabled MUST
retrieve a fresh random per-run canary token (making a content-absence
criterion falsifiable in the passing direction), and the restricted judge-config
arm MUST NOT. The old refusal-phrase criterion was dropped as distributional
noise (a toolless model narrates hallucinated tool transcripts ~50% of the
time; a flapping gate gets disabled). Honest scope, stated in the code: this is
config-drift regression detection, not adversarial containment proof — the
boundary is the tool policy; the canary detects drift in it.

All 100 pre-fix judge verdicts were quarantined
(runs/wave2-quarantine-judge/) and the entire judged set re-runs under the
fixed instrument — wave-1's 535-verdict re-judge precedent. Live validation:
4/4 two-arm probes PASS; leak line-of-detection verified intact by unit tests
(a token leak in the restricted arm raises immediately).
