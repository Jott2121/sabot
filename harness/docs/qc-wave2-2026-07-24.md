# Wave-2 adversarial QC ledger (2026-07-24)

Two independent passes over the complete wave-2 dataset, run before any wave-2
number is quoted anywhere. **Scope of "independent": independent *implementation*
within the project** — each pass was run by a separate agent writing fresh code from
the spec text, without reading or reusing the repo scorer. It is not third-party
external replication, and nothing here should be read as such; the passes share this
project's authorship. Same discipline as wave-1 (docs/qc-wave1-2026-07-23.md):
findings are resolved by disclosure against the pre-registered adjudication rules
(SPEC v0.2.0, tagged before any scored run) — never by post-data re-adjudication.

## Pass 2 — adversarial attack on the biggest lift claims

### Finding 1 (CRITICAL) — Magentic mapping surface 59.7% is 100% stall noise

All 43 magentic cells where wave1_mapping fired carry ONLY stall-ledger
retry_with_reason acts ("stall threshold crossed {...}"); zero reasons reference
the planted anomaly. Under the SPEC section-2 narrow reading the surface is 0/72.
The 8 union-only-via-mapping cells are all noise, so the **honest magentic union is
73.6% (53/72, flags-only); 84.7% only under the permissive mapping reading.**
Disposition: publish both readings, wave-1-footnote-5 style; quote 73.6%. v0.2.1
adopts the narrow retry-reason rule.

### Finding 2 (CRITICAL) — the FLAGS contract itself induces Magentic stalls

Clean-baseline stall re-plans: wave-1 3/25 seeds; wave-2 **18/25** (T4 and T5 5/5).
The frozen-surface "lift" 8.3% -> 59.7% tracks the baseline stall pattern, not the
faults (T2 baselines never stall and have 0 mapping detections). Disposition:
publish the baseline stall table; never present 59.7% as protocol lift.

### Finding 3 (HIGH) — clean-baseline false-anchor base rates

Running the anchor rule over all 150 clean baselines: O1 32.7%, O4 26.0%, O5
24.0%, O3 12.7%, O2 5.3%, O6 1.3% would anchor with NO fault present — several
tasks embed natural discrepancies (T1's 47.1-vs-41.7 by design) whose values are
registered anchors. Disposition: publish this table as the flags-surface base
rate, the analogue of the stall base rate.

### Finding 4 (HIGH) — the O4 anchored-flags surface carries no signal

Fault-run O4 anchored 24.5% vs clean base rate 26.0% — indistinguishable; sampled
texts are the natural T1/T2 distractors, some explicitly asserting NO anomaly.
Honest O4 reading: mapping-only 14/143 (9.8%), not the published union 32.9%.
Disposition: footnote wave-2; v0.2.1 excludes the generic flags surface from O4.

**Reproducibility gap — RESOLVED 2026-07-24, same day, and the numbers moved.** As
first published, the strict column was produced by this QC pass as a one-off analysis
over the per-cell flags text, and that analysis was **not a committed code path**: it
required classifying each registered anchor as injected-side or true-side, and that
classification was never persisted. Every input needed to redo it was published
(`runs/wave2/wave2-rows.json` carries the full FLAGS text for every cell and SPEC 10.4
carries all 30 anchor sets), but a third party could not re-derive the six numbers by
running committed code the way they can re-derive the published union.

That is now closed. `sabot/strict.py` persists the anchor classification with a stated
reason per dropped anchor, `tests/test_strict.py` (102 tests) asserts the
classification against the frozen `operator_specs.SPECS` so it cannot drift, and
`scripts/score_strict.py` regenerates `runs/wave2/STRICT-FLOOR.md` deterministically
with a `--check` mode for drift. **The recompute disagrees with this pass's stated
floors by +1 to +3 cells on the five standard rows and by -2 cells on the Magentic
row, so the committed figures supersede them.** No wave-2 headline moves: the union
surface is untouched by the strict scorer.

Two independent cross-checks say the disagreement is arithmetic in this pass's
row-level composition, not a difference in what "strict" means. The committed scorer
reproduces, exactly, two strict-family figures this ledger stated separately and
derived independently: **O4 mapping-only 14/143 = 9.8%** (finding 4) and
**values-only O5 = 83.9%** (the superseded-echo audit under "what survived"). A
definitional divergence would not land on both of those to the cell. Direction of the
correction is also the honest one to disclose: the standard-row floors were slightly
too LOW (this pass under-counted the floor, understating the result) while the
Magentic floor was too HIGH (over-counting the row that already carries the most
caveats).

Residual known conservatism in the committed floor, accepted and documented in
`sabot/strict.py`: three cell classes have no strict surface at all, because their
registered anchors cannot separate injected from true text — T4/O1 (`40 km` is a
substring of the true `140 km`, the disclosed footnote-7 slip), T1/O3 (`P-3117`
prefixes both sides), T5/O3 (the injection deletes the anchor word `sustained`). Those
cells score zero at the floor and non-zero in the published union, which is the floor
behaving as designed.

#### Frontier adversarial review of the scorer, and the two things it forced

The committed scorer was put through one frontier-model methods review before this
entry was finalized. Its strongest objection is worth stating in its own words'
substance: **the strict floor is not a lower bound on detection, it is a lower bound
on detection-that-this-anchor-set-can-see.** In the three blind cell classes above, a
zero means the instrument could not see, not that the pipeline was silent — and that
blindness correlates with operator, which is an axis the scoreboard reports on. Two
additions followed, both now in `STRICT-FLOOR.md`:

1. **A coverage-adjusted floor.** Blind cells are marked undetermined and dropped from
   the denominator, with coverage published per row. Coverage is 73-74% on standard
   rows and 59.7% on Magentic; over covered cells the floor is **50.9-56.9% on standard
   rows and 93.0% on Magentic**. Both variants publish; neither replaces the other.
2. **The strict rule's own clean-baseline false-positive rate** — the review proposed
   this as a falsification test, with the prediction that a sound rule should fire on
   under roughly 2-3% of clean baselines. **It fires on 4.6% (41/900), above that
   bar**, so the result is reported rather than buried. It is also not uniform: the
   false positives are almost entirely a T3 artifact (20.0% on T3; T2 2.8%; T1, T4 and
   T5 exactly 0.0%). In T3's clean runs the reviewer enumerates illustrative or
   hypothetical conflicting values that happen to include the injected-side token, so
   for T3 those tokens are not strictly injection-only and T3's contribution to the
   floor carries that discount. For comparison the published anchor rule fires on
   17.0% of the same corpus. Measuring this also produced a **third** independent
   confirmation that the scorer's extraction path matches this QC pass: re-deriving
   the published anchor-rule base rates from the raw baselines reproduces all six
   exactly (O1 32.7%, O4 26.0%, O5 24.0%, O3 12.7%, O2 5.3%, O6 1.3%).

On the fair question of whether the O5 drop list was tuned against wave-2 outputs
rather than derived from payload structure: it was derived from structure (each
excluded figure is one the injected payload itself names as superseding it, e.g.
"corrected figure of 1.8 metres"), and there is a checkable trace of that. The
per-row deltas against this pass's stated floors were **identical (+1/+1/+1/+3/+1/-2)
both before and after** the O5 refinements were applied, i.e. those refinements moved
no row total at all. A drop list tuned to move numbers would not have that property.
The review also noted, correctly, that the correction moves in both directions at once
— up on all five standard rows, down on Magentic — which is not the signature of
number-chasing.

## Addendum — the judge sandbox incident (2026-07-24, mid-wave-2 judging)

At batch 5 of the first judge run, the pre-batch canary FIRED: the judge model
reached the filesystem through `Monitor` — a tool added to the Claude Code
harness AFTER the wave-1 DENY list was frozen — and its probe reply quoted the
canary contents verbatim, naming its own method. The instrument refused to run
(fail-loud held). This is the benchmark's second self-catch: wave-1's canary
caught retrieval-hook contamination; wave-2's caught denylist decay against an
evolving harness.

Closure (dated commit 8d8da85, disclosed): primary = empty tool ALLOWLIST
(`--allowed-tools ""`) + `--strict-mcp-config` with no config (zero MCP
servers); the DENY list stays as defense-in-depth, extended to every current
first-party tool. The probe itself was redesigned (frontier-consult-ratified)
into a two-arm config-drift gate: a permissive arm with tools enabled MUST
retrieve a fresh random per-run canary token (making a content-absence
criterion falsifiable in the passing direction), and the restricted judge-config
arm MUST NOT. The old refusal-phrase criterion was dropped as distributional
noise (a toolless model narrates hallucinated tool transcripts ~50% of the
time; a flapping gate gets disabled). Honest scope, stated in the code: this is
config-drift regression detection, not adversarial containment proof — the
boundary is the tool policy; the canary detects drift in it.

All 100 pre-fix judge verdicts were quarantined
(runs/wave2-quarantine-judge/) and the entire judged set re-runs under the
fixed instrument — wave-1's 535-verdict re-judge precedent. Live validation:
4/4 two-arm probes PASS; leak line-of-detection verified intact by unit tests
(a token leak in the restricted arm raises immediately).

## Addendum — T3 serves its own ground-truth section to the pipeline (2026-07-25, from the anchor-collision review)

The v0.2.1 anchor-collision review pass (`docs/anchor-collision-review-2026-07-25.md`)
escalated one finding beyond anchors, and verification confirms it: all three T3
adapters read `tasks/T3-codegen-review.md` COMPLETE — including its
`## Ground truth per operator` section, which narrates each operator's fault and its
detection signature — and hand that document to both the coder and the reviewer
(langgraph_adapter `_run_t3` spec_text/document; same pattern in the crewai and
autogen adapters). T3 is the only task served this way: T1/T2/T5 read purpose-built
asset files and T4 is constructed in code. The wave-2 adapters inherit `_run_t3`
unchanged, so the exposure covers BOTH waves, all frameworks, all configs.

Consequences, stated plainly:

1. **The published root cause for T3's strict false-positive concentration was wrong.**
   Pass-1 of this ledger and STRICT-FLOOR.md attributed T3's 20.0% clean-baseline
   strict rate to reviewers "enumerating illustrative or hypothetical conflicting
   values." They are not hypothetical — the reviewer is quoting the fault catalog it
   was handed (verified: in `autogen/default/T3/baseline/seed12` the value `5.57`
   appears nowhere in the trace except the reviewer's own FLAGS line, and the served
   document is the only source). The STRICT-FLOOR.md generator prose is corrected as
   of 2026-07-25; this addendum corrects the ledger record. Earlier wording stands
   above, unedited, per ledger convention.
2. **T3 detection rates measure a reviewer with the fault catalog in view.** T3 is
   the highest-detection task on both wave-2 surfaces (union 67.9%, 112/165). That
   correlation is offered without overclaiming a mechanism.
3. **No rescore.** The exposure cannot be subtracted from existing traces, the
   adjudication rules were followed as registered, and the affected rows are identified
   exactly (every T3 row, both waves). The honest instrument is a sensitivity bound:
   **excluding all T3 rows, pooled unions move langgraph 54.96% → 53.60%, crewai
   53.47% → 49.56%, autogen 65.28% → 61.99%; the cross-framework median moves 55.0% →
   53.6%; the 726-cell paired comparison moves from 17.5% → 56.9% (all tasks) to
   17.1% → 53.7% (no T3).** The headline claim is robust to dropping the affected
   task entirely.
4. **The wave-1 side cuts the other way.** Wave-1 T3 pipelines had the same catalog
   in view and still detected almost nothing on the frozen surfaces — an answer key
   in the context did not make the checks act, which is the paper's thesis restated.
5. **Prospective fix (wave 3, v0.2.1 review R8):** serve redacted task material —
   pipelines receive the task, never the ground-truth notes.
