## Pass 2 — adversarial attack on the biggest lift claims

### Finding 1 (CRITICAL) — Magentic mapping surface 59.7% is 100% stall noise

All 43 magentic cells where wave1_mapping fired carry ONLY stall-ledger
retry_with_reason acts ("stall threshold crossed {...}"); zero reasons reference
the planted anomaly. Under the SPEC section-2 narrow reading the surface is 0/72.
The 8 union-only-via-mapping cells are all noise, so the **honest magentic union is
73.6% (53/72, flags-only); 84.7% only under the permissive mapping reading.**
Disposition: publish both readings, wave-1-footnote-5 style; quote 73.6%. v0.2.1
adopts the narrow retry-reason rule.

### Finding 2 (CRITICAL) — the FLAGS contract itself induces Magentic stalls

Clean-baseline stall re-plans: wave-1 3/25 seeds; wave-2 **18/25** (T4 and T5 5/5).
The frozen-surface "lift" 8.3% -> 59.7% tracks the baseline stall pattern, not the
faults (T2 baselines never stall and have 0 mapping detections). Disposition:
publish the baseline stall table; never present 59.7% as protocol lift.

### Finding 3 (HIGH) — clean-baseline false-anchor base rates

Running the anchor rule over all 150 clean baselines: O1 32.7%, O4 26.0%, O5
24.0%, O3 12.7%, O2 5.3%, O6 1.3% would anchor with NO fault present — several
tasks embed natural discrepancies (T1's 47.1-vs-41.7 by design) whose values are
registered anchors. Disposition: publish this table as the flags-surface base
rate, the analogue of the stall base rate.

### Finding 4 (HIGH) — the O4 anchored-flags surface carries no signal

Fault-run O4 anchored 24.5% vs clean base rate 26.0% — indistinguishable; sampled
texts are the natural T1/T2 distractors, some explicitly asserting NO anomaly.
Honest O4 reading: mapping-only 14/143 (9.8%), not the published union 32.9%.
Disposition: footnote wave-2; v0.2.1 excludes the generic flags surface from O4.

Counting only flags quoting injection-only tokens (O4 zeroed, magentic mapping
zeroed): standard rows 47.1-52.1% (published 53.3-55.6%); magentic 58.3%
(published 84.7%). Strict is a floor (discards genuine paraphrase detections);
published is the ceiling under pre-registered rules. Publish both.

**Reproducibility gap, disclosed rather than papered over.** The strict column was
produced by this QC pass as an analysis over the published per-cell flags text, and
that analysis is **not yet a committed code path** in the harness: it requires
classifying each registered anchor as injected-side or true-side, and that
classification is not currently persisted. Every input needed to redo it IS
published (`runs/wave2/wave2-rows.json` carries the full flags text for every
cell, and SPEC 10.4 carries all 30 anchor sets), but a third party cannot today
re-derive these six numbers by running committed code the way they can re-derive
the published union. Committing the strict scorer, with the anchor-side
classification persisted per cell, is a v0.2.1 item and is the highest-priority
one, since the strict/published pair is the sensitivity bound this project asks
readers to quote. Until it lands, the six values above should be read as this QC
pass's stated result, not as an independently reproducible figure.

## Addendum — the judge sandbox incident (2026-07-24, mid-wave-2 judging)

At batch 5 of the first judge run, the pre-batch canary FIRED: the judge model
reached the filesystem through `Monitor` — a tool added to the Claude Code
harness AFTER the wave-1 DENY list was frozen — and its probe reply quoted the
canary contents verbatim, naming its own method. The instrument refused to run
(fail-loud held). This is the benchmark's second self-catch: wave-1's canary
caught retrieval-hook contamination; wave-2's caught denylist decay against an
evolving harness.

Closure (dated commit 8d8da85, disclosed): primary = empty tool ALLOWLIST
(`--allowed-tools ""`) + `--strict-mcp-config` with no config (zero MCP
servers); the DENY list stays as defense-in-depth, extended to every current
first-party tool. The probe itself was redesigned (frontier-consult-ratified)
into a two-arm config-drift gate: a permissive arm with tools enabled MUST
retrieve a fresh random per-run canary token (making a content-absence
criterion falsifiable in the passing direction), and the restricted judge-config
arm MUST NOT. The old refusal-phrase criterion was dropped as distributional
noise (a toolless model narrates hallucinated tool transcripts ~50% of the
time; a flapping gate gets disabled). Honest scope, stated in the code: this is
config-drift regression detection, not adversarial containment proof — the
boundary is the tool policy; the canary detects drift in it.

All 100 pre-fix judge verdicts were quarantined
(runs/wave2-quarantine-judge/) and the entire judged set re-runs under the
fixed instrument — wave-1's 535-verdict re-judge precedent. Live validation:
4/4 two-arm probes PASS; leak line-of-detection verified intact by unit tests
(a token leak in the restricted arm raises immediately).
